# W-001 — Use `introduce` only when its semantics fit

**Status:** CONDITIONAL  
**Category:** Contribution / Vocabulary

## Original comment

A teacher/reviewer comment objected to `introduce` in a contribution statement because it did not precisely describe the technical action.

## Trigger example

> We introduce a module to improve reconstruction.

## Underlying concern

The problem is not the word itself. The concern is semantic imprecision: `introduce` can become a generic prestige verb that hides what the work actually does.

## External verification

### Official guidance

No explicit IEEE/TMI rule identified that bans `introduce`.

### Recent-paper evidence

Formal paper sampling is still pending for this entry. Existing field practice clearly contains both `introduce` and more specific verbs, so the rule must remain conditional rather than prohibitive.

## Assessment

**Judgment:** Context-dependent

**Reason:** `introduce` is natural when a paper genuinely brings in a new concept, term, component, or formulation. It is less informative when the real action is better described as formulate, develop, design, derive, implement, or evaluate.

## Current rule

Do not ban `introduce`. Prefer a more specific verb when describing a concrete methodological action or contribution. Use `introduce` when the contribution genuinely introduces a new concept, term, component, or formulation.

## Examples

### Avoid when this rule applies

> We introduce a module to improve reconstruction.

### Prefer

> We design a residual decoder to refine the interpolated estimate.

### Also acceptable when appropriate

> We introduce the concept of approximation-space-separated refinement.

## Scope

- Contributions
- Abstract
- Introduction
- Entire manuscript when `introduce` describes authors' actions
